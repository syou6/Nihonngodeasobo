## 1. プロダクトの変遷

このリポジトリは元々 **「日本語であそぼ」= AI音声日記アプリ**(Supabase認証 + Stripe課金 + NVIDIA NIM フィードバック)だった。ルートに残る `STRIPE_*.md` `FIREBASE_*.md` `PLAN.md` `README.md` の記述はすべてその時代のもの。

そこから **ピッチアクセント訓練**に軸足を移し、最終的に:

- **iOSアプリ**(別リポジトリ)= 本体プロダクト。サブスク専用。2026-08 App Store 公開
- **このリポジトリ** = LP + SEO記事 + マーケ動画生成

に役割が分かれた。

## 2. Webアプリを「隠した」判断(2026-08-02)

**問題:** iOSアプリが freemium → subscription-only になった。同じ訓練が無料で遊べるWeb版が本番に存在すると、有料アプリと直接競合する。加えてWebのStripe決済は設計上壊れていた(iOSアプリ側にアカウント・ログイン・サーバーが無いため、Webで払っても紐付け先が無い)。

**選択肢:** (a) コードごと削除 / (b) 非表示にして残す

**採用: (b)。** オーナーの明示的な指示。「とりあえず非表示にしていくイメージ、削除はしないでほしい」。

**実装:** `vercel.json` の redirects で `/app` `/app.html` `/app/*` `/subscription/*` → `/` に307。コードは1行も消していない。**redirectsブロックを削除すればWeb版は即座に復活する。**

**未処理として残っているもの:**
- Stripe/Supabase の環境変数は revoke していない。完全削除に踏み切る場合の候補リストはコミット `7236024` のメッセージに列挙してある
- `supabase/functions/` 配下の12個のEdge Functionsも未使用のまま残存

## 3. LPの設計思想

### ヒーロー = 商品説明ではなく「テスト」

箸/橋 の聞き分けを**1問だけ**出す。訪問者は着地から8秒以内に「聞き分けられなかった」を体験する。**その失敗こそがセールス論拠そのもの**で、以下のセクションはすべてその失敗のアフターケア。

**「Try another」は意図的に削除した。** これはデモであってプロダクトではない。1問だけ。スコアもストリークもリピートも無い。ここに機能を足したくなったら止まること。

### セクション順

1. ヒーロー(箸/橋テスト + CTA)
2. 聞き取れないことの代償(2文、具体的、恐怖を煽らない)
3. 3モード(Ear Sprint / Pattern Drill / Pitch Karaoke)— ドット輪郭モチーフ、絵文字禁止
4. 音声の作り方(検証ストーリー)— **ここが堀。競合が主張できない**
5. プライバシー(オンデバイス、アカウント無し、サーバー無し、機内で動く)
6. 価格(1製品 × 3課金オプション、年額先頭、トライアル終了時の挙動を明記)
7. FAQ(実際の疑問のみ)
8. フッター(Terms / Privacy / Legal / Contact)

### 事実の扱いについて

過去のLPには **「real native audio」(実際は合成音声)** と **「100+ minimal pairs」(実際は36)** という虚偽記述があり、修正済み。honest scoring を売りにするブランドで嘘が1つバレたら全部死ぬ。

証言・ユーザー数・評価の類は**一切載せていない**。実ユーザーがまだ居ないため。捏造は無い方がマシ。

## 4. waitlist機能を削った判断(2026-08-02)

App Store審査中の期間、「出たら知らせる」メール収集フォームを実装した(Vercel Function + Supabase)。

**その後すぐ撤去。** 理由: サイト流入がほぼゼロの状態でメール収集用のDBを立てて運用する価値が無い。オーナーの「いらないかもしれません」を受けて即削除。

`api/waitlist.js` と対応する vercel.json rewrite は削除済み。**その後アプリが承認されたため、この判断は結果的に正しかった**(waitlistの出番なくApp Storeボタンに直行できた)。

## 5. 集客の現状と試したこと

### 数字(直近の観測)

- **サイト流入はほぼゼロ**。GA4で確認、横ばい〜微減が続いている
- TikTok: 28日で約7,000再生 / **コメント0件** / プロフィール遷移21回 / シェア1件

### TikTokが伸びなかった原因(分析済み)

1. **コメントを求めた3秒後に自分で答えを明かしていた** → コメントする理由が消える
2. **18日間ほぼ同一のテンプレート動画** → アルゴリズムに「スキップされる見た目」を学習させた(SEOのdoorwayページ問題のTikTok版)
3. **人間が出ていない** → 顔・声・生っぽさを優遇する2026年のアルゴリズムに構造的に不利

### 対応として作ったもの(`marketing/`)

すべてコミット済み。生成物(423MB)は gitignore。

## 6. 次にやるべきこと(優先度順)

1. **チャネル別インストール計測を読む。** `/r/:tag` リダイレクトは実装済み・稼働中。App Store Connect の App Analytics でキャンペーン別のインストール数が見られるはず。**どのチャネルが実際に効いているかを数字で確定させる**のが最優先。憶測で動かない
2. **配信を止めない。** 過去の最大の失敗は「投稿を止めた瞬間にグラフが死んだ」こと。上記の tease形式・実プレイ録画・YouTube横展開の素材は生成済みで手元にある
3. **Reddit r/LearnJapanese への価値投稿。** 高意図・リンク可。1投稿でTikTok1ヶ月分の実ユーザーが来る可能性がある。文面は過去のセッションで作成済み(未投稿)
4. LPの改善は**流入が戻ってから**。誰も見ていないLPを磨いても数字は動かない

## 7. 判断の原則(このプロジェクトで繰り返し効いたもの)

- **証明できない主張は書かない。** 数字を刷る前に実データで裏を取る
- **削除より非表示**(オーナー方針)。gitに履歴が残っていても、戻せる形にしておく
- **完了報告の前に本番を実際に叩く。** ビルドが通った ≠ 反映された
- **新しい物を作る前に、既存の1本を閉じる。** 孤島を増やさない
